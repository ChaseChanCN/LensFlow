# 10 · 可量化设计验收清单

本清单用于CodeArts后续原生实现。所有小程序项目前均为“待验收”，不是DS-01已经通过的测试。项目尺寸和体验要求是PROPOSED_ADAPTATION；Web来源值见03／JSON。DS-01自身文件核验在末节单独记录，不混淆两类通过。

## 原生视觉与行为验收

| 编号 | 验收对象与可测条件 | 所需证据 | 当前 |
|---|---|---|---|
| A01 | 浅／深主题的page、panel、主次文字、按钮、状态配对与选定JSON resolvedValue一致；除经记录的原生系统控件外，hex色值不任意漂移 | 字典导出＋两主题截图；逐项比对必要语义色 | 待验收 |
| A02 | #007AFF与#6B7A99仅在各自已验证语义适用位置使用；主界面符合Material蓝灰／暖白／石墨层次；主按钮不是随意换色的系统默认绿 | 主题字典、主要按钮截图 | 待验收 |
| A03 | 同类按钮几何一致：胶囊、常规建议48px高，独立目标至少44×44逻辑px；disabled、loading、pressed、focus或可访问等价反馈分别可观察 | 触摸目标测量＋默认／按下／禁用／加载案例 | 待验收 |
| A04 | 业务卡片16px、图片容器约5px等场景几何一致；普通业务卡片无无依据大投影；任何偏离记录为适配 | 同页测量，不能仅凭感觉 | 待验收 |
| A05 | 页面、区块、正文、辅助四级文字稳定；建议28/20/16/14px；中文不照搬桌面-1.8px字距，关键说明不使用9–10px装饰眉题字号 | 中文／英文混排、大字截图 | 待验收 |
| A06 | 系统字体回退可用，不因缺SF Pro而缺字；编号、数量与单位可读，计数变化不引起不必要位移 | iOS与Android字形、长编号案例 | 待验收 |
| A07 | 表单每项有持久标签；错误与字段对应；网络失败保留已填内容；提交中不能重复发送；无接口数据时不展示价格与可售时段 | 空／校验错／断网／提交中／真实成功案例 | 待验收 |
| A08 | 所有订单状态使用准确中文；待选片不只显示“已确认”；未知状态不假定成功；下一动作依据服务端能力 | 05状态表每类数据样本＋动作条件 | 待验收 |
| A09 | 照片周围为中性#323232或已记录并获准的等效中性处理；照片节点无美化filter／色叠层／阴影；UI主题切换不改变作品像素 | 同一测试照片浅深主题并排＋样式证据 | 待验收 |
| A10 | 横图、竖图、全景、极长图完整适应，不裁边、不拉伸；显示宽高比例与源宽高比例误差≤1%（允许像素取整），不使用cover强裁切 | 四类授权测试图的源尺寸与显示测量 | 待验收 |
| A11 | 已选同时有边界、勾选／文字或等效非颜色信号；勾选热区≥44px；上限规则可读，取消仍可用；Set按稳定照片ID | 0张、1张、上限、取消案例 | 待验收 |
| A12 | 已选数量=实际唯一选择ID数；分页／预览返回／重试后保持；“已加载”与“总数”分别标注，缺总数不假报 | 至少跨两页选择，返回后ID与计数对照 | 待验收 |
| A13 | 选片冲突或提交失败不清空本地选择；重载只有成功后替换本地；成功结果由服务端确认，不能提前乐观声称已提交 | 断网、revision冲突、重载失败／成功案例 | 待验收 |
| A14 | 加载有对象说明；空列表、未发布、筛选无结果、无权限、资源失效、网络错误有区别；已加载项和成功项保留 | 每种状态的截图与下一步 | 待验收 |
| A15 | 交付预览与文件动作分开；文案区分“预览”“交付文件”“下载”“保存到相册”；过期／撤回／授权拒绝有清晰说明 | JPEG与文件包案例，取消授权／失效案例 | 待验收 |
| A16 | 首页影像优先、短品牌文案、清晰预约CTA；无粒子／重动画引擎依赖；图片失败时仍可进入预约 | 首屏、资源失败截图＋依赖清单 | 待验收 |
| A17 | 原生首页／订单／我的Tab及二级返回自然；无重复网页头栏；回到订单／图库保持上下文；独立LightTable／元数据编辑不出现在客户页 | 三Tab与五个嵌套流程录屏／路径表 | 待验收 |
| A18 | 所有页面顶部不与状态栏／胶囊重叠，底部CTA不被手势区／TabBar覆盖；键盘开启能看到当前输入与提交 | 刘海／非刘海设备，键盘开关对照 | 待验收 |
| A19 | 320／375／414逻辑px宽度与平板适当布局、大字设置下无关键文字截断或操作越界；照片比例保持；必要时退一列 | 明确设备和窗口宽度的截图矩阵 | 待验收 |
| A20 | 必读普通文字与背景对比≥4.5:1；重要状态不只颜色；读屏可识别返回、选择、数量与错误；装饰不打扰播报 | 对比计算（透明度需合成）＋真实读屏记录 | 待验收 |
| A21 | 动态效果关闭／减少后任务仍可完成；普通反馈不阻塞输入与返回，不用假百分比 | 静态路径操作记录与进度数据来源 | 待验收 |
| A22 | 分页与缩略图优先；长图预览不一次解码全部原图；低内存设备反复进入退出无明显持续资源堆积 | 指定低内存机型、连续操作记录和性能观察 | 待验收 |
| A23 | 小程序有自己的资源和组件，不导入LensFlow React、CSS、node_modules或跨仓库运行包；无不必要重动画依赖 | 依赖清单、构建输入与网络域名检查 | 待验收 |
| A24 | 正式品牌图资产有明确授权；测试／交付包不含客户私图、真实身份、凭据或媒体签名链接；原片没有为展示而被改写 | 资产清单与来源、隐私复核记录 | 待验收 |

A10的1%是本项目可执行的比例验收容差，不宣称为平台标准。A19是后续必须覆盖的目标矩阵，DS-01只观察1280×720与375×812的Web布局。44px是项目建议；W3C[SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)并非统一要求44px。普通文字4.5:1依据[SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；合成背景与真实读屏不能由一张截图替代。

## 对比度核验的实际范围

[静态配色结果](evidence/contrast-results.json)只计算本包明确列出的不透明色配对；普通主／次文字、主按钮、四类状态文字配对逐项记录。它不覆盖透明叠层、shader瞬时像素、全部hover/disabled、所有局部旧工具类或小程序系统控件，不宣称全站合规。任何低于门槛的组合必须保留在报告中并指出是否为仅基础／非当前使用组合，不能删样本或偷偷改Web。
