# 09 · Huawei CodeArts 原生设计接入指南

交接对象为独立开发的原生微信小程序；本包仅设计事实、视觉参考和适配建议，不含小程序页面实现。复制整个DS-01目录即可阅读，不要求运行LensFlow React，也不得建立LensFlow-WeChat→LensFlow的运行依赖。审计于2026-10-18开始，2026-10-19完成。

## 首先阅读的六项事实

1. 当前Web不是只有蓝色的白底系统。基础#007AFF操作蓝／#6B7A99品牌蓝灰仍存在，但活动Material默认深色，浅色使用暖白，常规filled按钮是中性底＋描边＋胶囊。
2. 品牌页、业务页、照片区三种密度和表面不同。照片周边始终#323232、完整比例、无滤镜；业务表面跟随主题。
3. 当前页面标题靠44px／500／留白建立层级，手机Web是35px；小程序建议28px，不复制桌面字号和负字距。
4. 业务卡片主要16px圆角、1px边，普通阴影被清空；按钮胶囊；照片卡5px；不要把基础12px卡片token当当前所有卡片最终值。
5. 客户Web选片仍是编号卡片，交付仍是文件信息＋下载。原生图片网格、大图交付和失效体验均属于有依据的适配建议，不是现成Web功能。
6. Three.js人物粒子、Beam、Metal、Gooey、鼠标光晕保留为Web效果。本任务明确排除粒子引擎、渲染管线、着色器、模拟与重动画替代方案。

## 必须采用的令牌与读取方式

权威JSON为 [tokens/lensflow-design-tokens.json](tokens/lensflow-design-tokens.json)。读取规则：

- `web.declarations`保留271条变量声明及逐行原文；`web.metrics`保留35个局部组件指标。306是含别名、作用域覆写的证据条目数，不是306种独立颜色。
- `web.effectiveThemes.light/dark`含按作用域展开的 `resolvedValue`、`originId`。先选择主题，再把必要最终值映射到小程序自己的语义命名。它仅展开变量，组件属性覆盖仍看metrics和04规格。
- `mobileProposals`是30个移动建议，值和单位单列；它们永远标为PROPOSED_ADAPTATION。`unresolved`有4个null值，不能转成0或任意默认数字。
- base中的纯CSS尺寸如`16px`已经带单位；不要再拼一次px。局部metrics／mobileProposals的数值如44则需按unit解释。字重、行高、图标画布线宽不是px。

| 必须一致的语义 | 浅色 | 深色 | JSON定位 |
|---|---|---|---|
| 页面／面板／控件 | #f5f4f0／#fffefa／#efeee9 | #101217／#171a21／#20252f | effectiveThemes中的--mat-page／panel／control |
| 主文字／次文字 | #202b3b／#596577 | #f0f1f3／#a0a8b7 | --mat-text／--mat-muted |
| 主按钮文字／边界 | #202b3b／#8796ab | #edf2fa／#7586a0 | --mat-button-text／--mat-button-border；底色为--mat-control |
| 强调／焦点 | #435f88／#365d98 | #b5c8e7／#a8c7f5 | --mat-accent／--mat-focus |
| 面板边界／分隔 | #c5ccd4／#d8dcdf | #343c49／#2b303a | --mat-border／--mat-line |
| 照片周边 | #323232 | #323232 | metric/photo.canvas |
| 业务几何 | 卡16px、按钮999px、1px面板边 | 同左 | metric/card.materialRadius、metric/button.radius；边值见规格 |
| 反馈与状态 | 四类bg/label成对使用 | 四类bg/label成对使用 | --color-success/warning/error/info-bg与-label |

不要单独移植某个前景色而遗漏背景，尤其不要依据`white`、`inverse`、`neutral-dark`等旧名称猜值。工作区不应变成系统默认绿按钮或单一#007AFF填充。完整排版、边距、时长和主题表在 [03](03-token-reference.md)。

## 组件与页面接入顺序

先实现小程序自身的表面／字体／语义色字典，再按 [04组件规格](04-component-specification.md)建立Button、字段、状态Badge、订单分组、照片卡／网格、预览、空／错／加载反馈。20类中Tabs无Web共享实现，不能声称“照抄现成Tabs”。状态矩阵中“—”只代表未实现或不适用；为小程序补充的状态必须在小程序设计文档中标为适配。

按 [05八页指导](05-mobile-screen-guidelines.md)落地：一级首页／订单／我的；预约、订单详情、选片、预览、交付入栈。先打通可见信息层级和状态，再接真实服务数据；此处“接入”是交付给CodeArts的实施建议，DS-01不编写这些页面。所有客户动作取服务端能力，摄影师后台状态操作、评分、索引和元数据编辑都不进入客户页。

## 平台适配与明确排除

采用原生导航／TabBar／页面栈、合适输入／picker／预览与文件动作；安全区按真实窗口处理，建议44px触摸下限，客户业务内容可随字体放大。所有rpx示例、48px按钮／28px标题等为提案；[06映射](06-platform-mapping.md)保留px与rpx的换算边界、设备内存和微信能力核验入口。

不复制React Router、浏览器Portal、localStorage、DOM焦点陷阱实现、TanStack Virtual实例、Web Blob下载、桌面键盘快捷键与管理导航。保持功能含义即可，不建立共享运行包。Three.js/WebGL/GLSL、任何粒子数据表示、滚动粒子变形、性能调优和重动画引擎均不在交付范围。

## 必须匹配、可以变化、不得复制

| 必须匹配 | 可按原生平台变化 | 不得复制 |
|---|---|---|
| 主题表面／文字配对和克制蓝灰层次 | 系统跟随或手动主题的默认策略（需产品确认） | 旧文档的纯白＋强蓝一套全覆盖 |
| 胶囊按钮、16px业务面板、小圆角照片语义 | 实际按钮高度、页面标题、留白和手机列数 | 28px桌面查看行直接当触摸目标 |
| 图片完整比例、中性周边、清晰选中和计数 | 手机图片翻页／缩放与原生预览方案 | 滤镜、强裁切、复制编辑器／LightTable |
| 文本状态＋有因果的加载／错误／成功反馈 | sheet/dialog、导航转场、授权和文件操作形式 | 泛化的错误“已确认”Badge、假进度条、假成功 |
| 图像优先、短文案、单个主要任务 | 静态品牌图、手机构图与短淡入 | 粒子／光束／液态装饰运行依赖 |

## 已知冲突与未决责任

完整18项漂移见 [08](08-design-drift.md)，其中D01/02/06/08/09/10/11对客户一致性影响最大。历史P5 NOT_ACCEPTED及历史性能／读屏问题只记DOCUMENTED_ONLY；本包不对并发后端工作流结果作接受或拒绝结论。

| 未决项 | 当前证据 | 由谁／何时确认 | 在确认前的做法 |
|---|---|---|---|
| 已批准手机静态品牌资产 | 没有可确认的可分发交付件 | 品牌／资产负责人，首页最终视觉签收前 | 用品牌文字与留白；不生成或擅截肖像 |
| 最低基础库、导航配置和主题策略 | 本轮非微信环境，官网部分正文未取得 | CodeArts／产品，在平台实现前 | 原生优先、静态token可回退；不承诺所有WXSS能力 |
| 客户缩略图、预览、文件有效期与资源权限 | Web客户选片无图片，交付无画廊；另一个流程正更新桥接API | 后端／小程序负责人，在接媒体前确认当前契约 | 采用安全接口，不猜URL、不暴露storage_key或签名令牌 |
| 价格、可售排期和时间段 | Web只有期望日期、类型、时长与联系方式 | 业务／后端，在预约功能签收前 | 不显示价格／可售日历，明确待确认 |
| 客户状态用词与下一动作 | Web通用Badge映射压缩多种状态 | 产品／后端，客户旅程验收时 | 依05建议使用真实状态中文，并按服务端能力给动作 |
| 字体放大、读屏、触屏、低内存实机 | DS-01只有Web浏览器和源码证据 | CodeArts／测试，发布前 | 按10清单记录真机结果，不把历史报告当本轮通过 |
