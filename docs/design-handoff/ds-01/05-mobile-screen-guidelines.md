# 05 · 客户小程序八个页面的视觉指导

本文件全部页面结构与移动尺寸均为 PROPOSED_ADAPTATION。每页“Web依据”中的实现事实才属于 VERIFIED_SOURCE。首页／订单／我的三Tab及预约、订单详情、客户选片、照片预览、交付五个嵌套流程来自本次任务要求，不是Web既有信息架构。

## 共同页面骨架

优先原生导航栏和原生TabBar；不要叠加Web的74/88px导航。一级Tab为“首页／订单／我的”，二级页使用页面栈。页面主区延续Material暖白或石墨主题，照片预览独立中性灰。建议横边16px、分区24px、卡片16px内边与16px圆角，常规主标题28px/500、区块20px、正文16px、辅助14px；这些建议值均可在[令牌适配层](tokens/lensflow-design-tokens.json)找到。

固定底部操作不得覆盖内容；需为操作区、设备安全区、存在的原生TabBar分别留出空间，按页面真实窗口与组件布局核算，不能重复叠加。单页只保留一个视觉上的主要动作。正文放大后允许多行及纵向伸展，不把页面标题或状态硬锁一行。

## 1 · 首页

| 项目 | 指导 |
|---|---|
| 视觉目的 | 品牌先行，让客户一眼理解“预约到交付”的摄影路径，马上找到预约或当前订单。 |
| 信息层级 | 品牌标记→单幅摄影／已批准品牌图→一句主标题→一段短介绍→预约动作→与客户相关的订单捷径→精简流程。 |
| 推荐结构 | 原生顶栏下的单幅品牌区；文案独立绘制；首要“预约一次拍摄”；若有进行中订单，显示一条“继续选片／查看交付”等真实下一动作。三步介绍可纵向排列，避免大面积统计面板。 |
| Web依据 | `frontend/src/pages/LandingPage.tsx:6-34`的三步流程、短句和主次动作；`site.css:37-50,64-80`图文构图；PublicShell品牌。当前Web主CTA是“开启创作空间”，小程序改预约是适配决策。 |
| 移动适配 | 手机采用上图下文，图片不作为按钮背景；静态品牌图优先，允许短淡入。品牌图未获批准时用现有文字标记与留白，不能自行生成肖像。 |
| 排版 | 主标题28px/500，可两行；副文16px、行高约1.6；英文眉题只作装饰，不承载重要操作条件。 |
| 主操作 | 品牌介绍之后单个48px胶囊CTA；屏幕短时允许自然滚动，不锁死720px hero高度。订单入口为次动作。 |
| 图片呈现 | 一张构图明确的品牌影像，保持主体焦点；品牌素材裁幅须获准。客户照片若被用作首页内容，必须另有公开使用授权。 |
| 加载／空／错 | 品牌图未加载时先呈现文字／CTA和稳定占位；订单不存在就不显示假统计；订单请求失败显示局部重试，不影响预约入口。 |
| 无障碍 | 品牌图的替代描述取决于是否承载信息；装饰粒子不进入读屏；标题与CTA不烧进图片；对比度和字号缩放按10验收。 |
| 反例 | 桌面粒子引擎、强制播放视频、大型泛营销数据看板、轮播多个同等重要CTA、私自生成“品牌照”。 |

## 2 · 订单（一级Tab）

| 项目 | 指导 |
|---|---|
| 视觉目的 | 快速找到“这是哪次拍摄、目前到哪一步、我现在能做什么”。 |
| 信息层级 | 订单身份→准确客户状态→拍摄／创建日期等可靠摘要→下一动作；金额、封面、时段只有接口提供才出现。 |
| 推荐结构 | 页标题→可选少量筛选→单列订单卡／分组列表→分页反馈。每条最多一个主行动，整条可进入详情，主行动与详情点击区域清晰分开。 |
| Web依据 | `OrdersPage.tsx:44-57`的订单编号／状态／日期；`ClientPage.tsx:108-125`的客户订单；ListGroup/ListItem的平面分组。 |
| 移动适配 | 不迁移管理表格、摄影师操作或英文内部状态码。过滤若需要，采用轻量原生或可访问控件；不能假设存在Web统一Tabs组件。 |
| 排版 | 编号／订单标题16px/500；状态与时间14px；次级说明可换行。状态Badge不承担全部信息。 |
| 主操作 | 当前可执行动作放卡片底部或行尾足够热区；“待选片”对应“开始／继续选片”，“已交付”对应“查看交付”；由服务端能力决定是否可用。 |
| 图片呈现 | Web订单列表没有已验证的封面模式。小程序仅在API提供授权封面时使用；没有封面以文本列表为准，不能随机选客户原片作封面。 |
| 加载／空／错 | 首次稳定占位；无订单解释预约确认后生成；筛选无结果可清筛选；下一页失败保留已有列表并提供就地重试。 |
| 无障碍 | 状态文字＋颜色；每个动作含订单身份；长编号可换行、触摸热区44px；回到列表恢复位置与筛选。 |
| 反例 | 所有状态Badge都写“已确认”、复杂桌面表格、同时显示上传／分析／归档动作、加载6张误当总数。 |

### 状态文案与下一动作建议

左两列来自Web状态映射（VERIFIED_SOURCE：`OrdersPage.tsx:7-20`、`Badge.tsx:27-54`）。右两列是PROPOSED_ADAPTATION；不是业务权限、状态机或新API的实现承诺。

| 原始状态 | Web当前通用Badge倾向 | 建议客户主状态 | 建议下一动作 |
|---|---|---|---|
| PENDING_CONFIRM | 待确认／warning | 待确认 | 查看预约／订单，等待确认 |
| CONFIRMED | 已确认／accent | 已确认 | 查看拍摄安排；仅显示真实安排 |
| WAITING_SHOOT | 已确认／accent | 待拍摄 | 查看拍摄信息 |
| WAITING_UPLOAD | 已确认／accent | 拍摄后处理中 | 查看进度，无客户上传动作 |
| ANALYZING | 分析中／warning | 照片处理中 | 查看进度 |
| WAITING_REVIEW | 分析中／warning | 照片整理中 | 查看进度，不暴露复核控制台 |
| WAITING_SELECTION | 已确认／accent | 待选片 | 有可用选片集时“开始／继续选片” |
| WAITING_RETOUCH | 修图中／warning | 已提交选片，待修图 | 查看已提交记录（接口支持时） |
| RETOUCHING | 修图中／warning | 修图中 | 查看进度 |
| WAITING_CLIENT_CONFIRM | 修图中／warning | 待确认修图 | 仅在客户确认流程可用时给明确入口 |
| WAITING_DELIVERY | 已确认／accent | 待交付 | 查看交付进度 |
| DELIVERED | 已交付／success | 已交付 | 查看交付，下载动作受文件能力约束 |
| ARCHIVED | 已完成／success | 已归档 | 查看历史详情；不推定仍可下载 |
| CANCELLED | 已取消／error | 已取消 | 查看记录／重新预约入口 |

未知状态显示中性“状态待更新”与可重试说明，并记录接口兼容问题；不要把未知值猜成完成。

## 3 · 我的（一级Tab）

| 项目 | 指导 |
|---|---|
| 视觉目的 | 提供最少而明确的账户、订单历史及帮助入口。 |
| 信息层级 | 登录／账户状态→当前订单捷径或历史入口→隐私／设置／支持。 |
| 推荐结构 | 紧凑账户分组＋订单历史分组＋服务分组。未登录显示登录动作；不要虚构积分、粉丝、会员等级。 |
| Web依据 | `ClientPage.tsx:54-128`的“我的”、概览、预约、订单及快捷入口；Web没有独立完整设置／隐私中心页面。 |
| 移动适配 | 将Web混在“我的”的订单主列表移到“订单”Tab，保留历史／快捷入口；设置、隐私、支持均为新平台建议，落实后才能显示可用链接。 |
| 排版 | 页面标题28px/500；账户名称20px；普通入口16px；次文14px。较少装饰眉题，不复制桌面统计卡。 |
| 主操作 | 未登录时登录为主；已登录时以入口列表为主，退出／解除关联使用次级或危险语义。不要持续显示抢眼“升级”按钮。 |
| 图片呈现 | 没有头像来源时使用克制的默认账户符号或文字；不擅取微信头像，也不随机使用客户照片。 |
| 加载／空／错 | 账户加载占位不显示假姓名；登录失效解释并引导重新登录；订单历史空态与账户错误分开。 |
| 无障碍 | 每个入口可独立读出名称和目的；文本放大可换行；主题切换有当前状态。隐私相关动作使用平台真实交互。 |
| 反例 | 社交主页、粉丝徽章、未接通支持入口、主动采集本任务未要求的个人信息。 |

## 4 · 预约

| 项目 | 指导 |
|---|---|
| 视觉目的 | 降低填写负担，准确表达“提交需求后等待摄影师确认”。 |
| 信息层级 | 服务说明→拍摄类型／日期意向→地点与时长→联系方式→可选备注→提交结果。 |
| 推荐结构 | 原生导航标题“预约”；相关字段分组；每组可见标签；必要项明确；可选字段渐进展示。提交前能复核关键输入。 |
| Web依据 | `BookingPage.tsx:10-18,28-42,65-142`：类型、期望日期、地点、0.5小时步进、必填联系方式、备注、成功提示与延迟返回。无价格和时段库存控件。 |
| 移动适配 | 日期用原生选择；若后续有时段API再独立展示时段及占用反馈。没有可用库存证据时只称“期望日期”，不能显示假可预约日历。小程序可用明确确认结果替代Web1.5秒自动返回。 |
| 排版 | 主标题28px，字段标签14–16px，输入16px，错误说明14px；输入行48px起，长备注不压缩为单行。 |
| 主操作 | 表单结束处“提交预约”，短屏可随文滚动；若使用固定底栏需避免键盘与安全区遮挡。提交中保持大小、禁重复，失败保留内容。 |
| 图片呈现 | 预约不是画廊，最多简短服务参考且来源获准；不让大肖像把表单推离用户。 |
| 加载／空／错 | 初始选项缺失时说明并可重试；字段校验就地；网络失败保留表单；成功显示真实编号和“待确认”，不伪装成预约已锁定。 |
| 无障碍 | 标签持久可见；错误与字段关联；首个错误可定位；日期、数字输入适当；时长单位写清。支持系统文字放大。 |
| 反例 | 虚构价格／可售时段、把提交需求写成支付成功、仅placeholder、成功无真实编号、错误后清空所有字段。 |

## 5 · 订单详情

| 项目 | 指导 |
|---|---|
| 视觉目的 | 成为客户理解当前订单与下一动作的唯一稳定锚点。 |
| 信息层级 | 订单编号→客户可读状态→当前待办→拍摄安排／预约摘要→历史／交付入口。 |
| 推荐结构 | 顶部身份与状态；一个任务卡；分组信息；按需展开历史。内部分析、元数据、归档管理不放在客户页。 |
| Web依据 | `OrderDetailPage.tsx`的LargeTitle、订单信息、NEXT_ACTIONS、选片与修图／交付分组、操作记录；`ListItem`结构。当前源码存在客户可见入口与角色判断分布不完整的问题，见D11。 |
| 移动适配 | 只呈现客户能力对应的动作；以服务端能力和可用资源判断，不单凭一张状态颜色。时间线面向客户用易懂文本，内部action code不原样呈现。 |
| 排版 | 编号20px或主标题28px；主状态16px；字段16px；日期与历史14px。大量字段使用分组，不将每一项放成独立浮卡。 |
| 主操作 | 待选片／待确认／可交付时在顶部任务卡或底部安全区域给一个主要CTA；其他状态展示明确等待说明。 |
| 图片呈现 | 只有安全封面／缩略图可使用；没有则文本优先。图片不作操作状态的唯一线索。 |
| 加载／空／错 | 详情／历史可分区加载；历史为空不表示订单不存在；无权限、已删除、网络失败需要不同说明及返回列表，不能泄露其他客户摘要。 |
| 无障碍 | 状态含中文，长编号换行；返回按钮始终可达；历史按时间顺序可读，重要下一动作44px以上热区。 |
| 反例 | 客户页面显示“开始修图／上传原图／归档”、把状态更新按钮当真正文件交付、展示未经核实的排期和价款。 |

## 6 · 客户选片

| 项目 | 指导 |
|---|---|
| 视觉目的 | 用最少遮挡让客户准确选择作品，并随时理解数量和提交状态。 |
| 信息层级 | 订单身份与规则→已选x／允许y张→图片网格→预览／选择→复核提交。 |
| 推荐结构 | 紧凑说明区；默认两列缩略图，每图独立勾选；常驻已选计数和单个“提交选片”；点击图像打开预览，返回恢复位置和选择。 |
| Web依据 | `SelectionPage.tsx:27,47-67,74,83,87-118`已有本地Set、上限、计数、提交禁用、服务端revision与重载；但`:89-110`没有任何图片节点。图片规则借鉴摄影师`AssetGrid`和`photo-library.css:11-12`，不能冒充客户现成画廊。 |
| 移动适配 | 新增图片呈现需使用客户获授权缩略图；网格8px gap、默认两列是提案；极窄屏或大字可退一列。计数以稳定photo id集合计算，分页不能丢选，提交成功才进入完成态。 |
| 排版 | 页标题可简化为原生栏；规则与计数16px，编号／辅助14px；所有“上限／剩余／已提交”说明可读，不能仅sr-only。 |
| 主操作 | 底部安全操作区显示“已选x／y”及提交；0张、处理中、已提交时按真实条件禁用。超上限给明确原因且已选项仍可取消；最终提交前复核是建议。 |
| 图片呈现 | contain或等价完整适应；中性#323232周边，比例取图片真实尺寸。容器可采用统一格高，但不得裁掉照片；勾选在保留区域，避免脸部和主体；用边框＋勾选＋文字冗余表达选中。 |
| 加载／空／错 | 稳定占位保留比例；单图失败局部重试，已有选择不丢失；未发布／空集／过期／无权限／网络失败分别说明；revision冲突保留本地草稿供核对，重载失败不清空选择。 |
| 无障碍 | 独立44px勾选热区；每张有可读编号和已选状态；计数更新可播报；不依赖长按、双击或颜色；预览返回焦点／位置可恢复。 |
| 反例 | Web编号空卡直接当最终交付、强制方形cover、蒙版压暗已选照片、分页重置Set、未请求完成就显示“提交成功”。 |

## 7 · 照片预览

| 项目 | 指导 |
|---|---|
| 视觉目的 | 看清完整作品，并在浏览时保留选片上下文。 |
| 信息层级 | 完整照片→关闭／返回→当前索引x/y→已选状态／选择动作→必要质量说明。 |
| 推荐结构 | 原生独立预览页或经确认可满足选择需求的平台预览；图片居中、工具在独立顶底区域；支持前后浏览；不展示摄影师的评分、EXIF、关键词编辑。 |
| Web依据 | `PhotoViewer.tsx:9-36`按比例Canvas、尺寸信息、前后按钮、局部加载；`photo-library.css:16-19`中性灰背景；Web已有的是摄影师Modal，客户手势体验未实现。 |
| 移动适配 | 触摸前后浏览／缩放取目标组件可用能力；选择按钮与浏览手势分开。若原生预览无法稳定显示自定义选择，采用独立原生页面组成，而不是在截图上模拟控件。 |
| 排版 | 编号／索引14px，关键动作16px；必要质量说明14px，不用9px眉题。 |
| 主操作 | 选片入口来的预览，底部提供“选择／取消选择”；纯交付预览中只给对应查看／下载入口，不混淆动作；关闭始终44px热区且考虑胶囊安全距离。 |
| 图片呈现 | #323232、完整contain；无滤镜、阴影、品牌色叠层；低清先行可行但须标明“预览”，不宣称原片质量；不拉伸、不拼合修改照片。 |
| 加载／空／错 | 预览读取不阻塞返回；单张失败给就地重试／下一张；资源失效保留编号与原因；只加载附近必要图片，避免同时解码大量原图。 |
| 无障碍 | 原生读屏可识别返回、编号和已选；工具与背景有对比；没有滑动能力时仍有前后按钮或等价明确入口。 |
| 反例 | 移植双图LightTable、画布模拟全部手势、模糊预览直接标“原片”、关键操作只随hover出现。 |

## 8 · 交付

| 项目 | 指导 |
|---|---|
| 视觉目的 | 清楚区分“看成片”“取文件”“交付是否仍可用”。 |
| 信息层级 | 订单／交付状态→安全预览→文件名称／数量／格式／大小／时间（只显示真实字段）→下载／保存／打开→限制或到期说明。 |
| 推荐结构 | 简短交付说明与状态；若接口支持则展示大幅成片与网格；文件信息分组；预览和文件操作分开。当前无资源时显示等待交付。 |
| Web依据 | `DeliveryPage.tsx:91-110`空态、错误、订单状态、文件名、交付时间与下载；`api/deliveries.ts:38-41`认证Blob；没有Web已实现的大图画廊、到期文案或保存相册能力。 |
| 移动适配 | 文件类型决定原生“预览／保存图片／打开文件／下载”动作；使用后端授权的客户媒体与有效期。不可将浏览器Blob下载逻辑直接搬来，也不把下载ZIP按钮称作保存相册。 |
| 排版 | 状态16px，文件名16px可断行，辅助字段14px；下载说明与失效原因14px以上；不大面积展示庆祝插画。 |
| 主操作 | 有效交付的文件操作为一个主要CTA，预览为次；下载中显示真实状态并避免重复；取消授权／失败有明确返回。 |
| 图片呈现 | 预览大图完整显示，周围中性；下载质量由实际交付文件定义；标“预览图”与“交付文件”区别，数量和清晰度不靠猜测。 |
| 加载／空／错 | 未交付是空态，网络失败有重试，已过期／撤回是不可用态，权限不足单列；本地保存失败不意味着服务端文件已丢失。未知到期值不伪造日期。 |
| 无障碍 | 每个文件动作含名称／类型；成功文案说明“已下载”“已保存到相册”具体结果，不只绿色；主要动作和失效原因可读。 |
| 反例 | 展示摄影师上传／归档入口、把预览图充当原始交付、宣称所有文件都能直接存相册、隐藏过期／撤回状态。 |
