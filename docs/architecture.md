## 分层职责

| 层 | 职责 | 技术 |
|---|---|---|
| 前端页面 | UI 渲染、用户交互 | React + Tailwind + AntD |
| API 客户端 | HTTP 请求、JWT 拦截、错误处理 | Axios |
| API 路由 | 请求路由、参数校验、权限检查 | FastAPI |
| 服务层 | 业务逻辑、状态机、图像分析、存储、通知 | Python |
| 数据层 | ORM、迁移 | SQLAlchemy + Alembic |
| 基础设施 | 数据库、对象存储、通知渠道 | PostgreSQL/OBS/Bark |

## 设计原则

1. **单体架构**：前后端各一个单体，不引入微服务。
2. **抽象层隔离**：Storage 和 Notifier 通过抽象接口隔离具体实现，本地开发不依赖云服务。
3. **状态机集中**：所有订单状态流转走 OrderStateMachine，禁止直接修改 status。
4. **通知与状态解耦**：通知失败不影响订单状态流转。
5. **不删原片**：AI 初筛仅给建议，摄影师复核决定，原片永不自动删除。
