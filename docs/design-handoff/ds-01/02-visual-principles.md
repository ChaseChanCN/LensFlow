# 02 · LensFlow 视觉语言与跨端原则

这里的品牌解释标为 INFERRED；每项均列出可追溯的 Web 证据。小程序做法全部为 PROPOSED_ADAPTATION。图像、文字、操作的先后关系比“同一个蓝色”更能保持产品识别。

## 三种场景必须分别处理

| 场景 | 当前 Web 的具体构成 | 希望保留的感受 | 小程序解释 | 应避免 |
|---|---|---|---|---|
| A 品牌／介绍 | `LandingPage.tsx:16-32`的大肖像、短标题、单个装饰主操作、三步创作流程；`site.css:37-50`的大片留白和图文叠层 | 先看影像，再读一句话，最后选择动作；创作路径清楚 | 单张获准品牌图＋短文案＋预约CTA；可以保留淡入，提供静态默认 | 大量统计卡、促销轮播、三维引擎作为首页加载前提 |
| B 应用／业务 | `Layout.tsx:24-76`导航；`site.css:2-21`标题、分组卡片与胶囊控件；`ClientPage`预约／订单层级 | 条理与信任来自信息分组、状态文案、可预期的下一步 | 暖白或石墨主题；订单、预约、账户以文本和动作优先 | 交易信息置于肖像和发光叠层上；全页纯黑暗房化；无差别套白色大卡片 |
| C 摄影／画廊 | `photo-library.css:11-17,35`及`photo-editor.css:13-15`：#323232、contain、无滤镜无阴影 | 图像本身成为色彩和细节的判断对象 | 中性缩略图周边、大图完整显示、明确选择标记和计数 | 暖白蒙版覆盖图片、统一强裁切、为“品牌统一”给客户作品调色 |

以上对应关系为 VERIFIED_SOURCE；首页、工作台、客户页及图库的指定画面另有 [VERIFIED_RENDER](07-reference-index.md)。品牌肖像不意味着所有业务页都必须有肖像；摄影区的灰底也不意味着表单必须深色。

## 可执行的视觉原则

| 原则 | 现有 Web 证据 | 设计含义（INFERRED） | 移动端做法（PROPOSED_ADAPTATION） | 反例 |
|---|---|---|---|---|
| 内容先于装饰 | `LandingPage.tsx:19-24`先短文案与CTA；`EffectSurfaces.tsx`装饰层aria-hidden、inert、pointer-events:none；`PhotoViewer.tsx:31-34`图像后才是元信息 | 装饰为创作建立气氛，操作仍清楚可达 | 首屏在图片加载前显示标题与预约；按钮文案独立绘制；加载失败仍可操作 | 文字烧进不可读海报、动画未完成不显示入口 |
| 低饱和层次 | `material.css:10,21-58`的暖白／石墨底与蓝灰强调；状态色只用于小面积反馈 | 大面积由表面亮度区分，强调色用于意义明确的位置 | 整体采用当前Material配对；用有文字的状态Badge，不随意增加新色 | 主按钮、所有标题和每个图标都涂#007AFF；彩虹状态卡 |
| 非粗黑的编辑式标题 | `site.css:3-4,59`：44px/500、1.25、负字距，副文13px/1.8；`material.css:72`等宽英文眉题 | 大小、留白、密度差构成层级，而非全靠700字重 | 主标题建议28px/500；中文不照搬负字距；区块20px，正文16px | 把Web9px英文眉题用作中文日期；每一行都大粗体 |
| 外松内紧 | `material.css:76,81-89`大标题区与统计区；`site.css:5-11`组间24px、匹配行20×24px；图库12px网格 | 页面可以呼吸，行内信息仍聚合 | 页边16px、组间24px、卡内16px；图网8px为提案 | 所有元素同一24px间隔；在每个表单字段外再套独立大卡 |
| 场景化几何 | `site.css:8,14,48`：卡16px、按钮胶囊、品牌卡18px；`material.css:142`登录20px；`photo-library.css:7`图片卡5px | 软控件、克制面板、清晰照片边界各有角色 | 业务面板16px、按钮胶囊、照片容器5px；不扩大照片裁切 | 所有内容统一999px或20px，连照片也裁成头像 |
| 平面层叠 | `material.css:59`与`site.css:8,14`清空普通卡片／按钮阴影；Modal独立遮罩和阴影 | 靠边框和背景分层，模态任务才提升层级 | 普通列表平面边框，原生确认框优先；固定CTA与内容留足间距 | 每张卡都大投影；在照片上投下品牌色光晕 |
| 数字读起来稳定 | `material.css:87`tabular-nums、58px/350；`PhotoViewport`与编辑器CSS的等宽数字输出 | 工作区数量和状态变化不应抖动 | 数量与总数并列，保留单位；小程序“已选x/y张”常驻 | “已加载6张”伪装成“总计6张”；用随机百分比替代真实状态 |
| 摄影内容不被美化控件改写 | `photo-library.css:12,17,35`与`photo-editor.css:15`，明确filter:none/box-shadow:none | 作品展示重于模板装饰 | 预览完整长宽比；失效占位保留几何；照片和UI主题分开 | 美颜、提亮、混合模式或强制cover造成误判 |
| 反馈短且有因果 | `Button.tsx:55-65`loading/disabled、150ms与0.97；`Toast.tsx:16-46`暂停与关闭；`PageState.tsx:4-9`重试 | 点击要被看见，失败要有下一步 | 按下100ms、普通切换150ms；提交期间保留文案与位置；错误文本常驻到处理 | 多层弹窗＋Toast重复报错；请求未结束就播成功 |
| 动效为状态服务 | `QuickActions.tsx`静态降级，`useEffectMotion.ts`减少动态效果／后台暂停；`EffectSurfaces.tsx`延后装饰挂载 | 创作的流动感不应消耗每个动作的注意力 | 静态为默认，必要时短透明度／边框反馈；切换主题不闪烁 | Gooey或Metal变成底部Tab交互必需，动画锁住返回 |

## 首页粒子肖像的美术职责及边界

VERIFIED_SOURCE：`ParticlePortrait.tsx:9-18,36-47`依主题选择两套iframe入口；浅色为`reference4`，深色为`original`。`site.css:74-80`针对reference4取消人物遮罩，调整文字侧渐变。浅深组合已经发生源选择差异，不能把早期“同一肖像反相”文档当当前事实。本次只检查嵌入点及视觉结果，没有审查或导出粒子内部算法。

INFERRED：肖像把光、颗粒和人物轮廓放在同一构图中，暗部强调专注与观看，暖白模式让人物从纸面般背景中显现；右侧中文短句与左侧人物形成编辑式图文关系。蓝灰更像光与材料的语调，而非广告按钮的大面积品牌色。小屏Web改为上图下文，不应直接照抄其720px hero高度。

PROPOSED_ADAPTATION：优先用经批准的单张静态品牌肖像；由资产所有者提供合适裁幅和焦点，允许对品牌图选择适合手机的构图，但不得借此裁切客户作品。其次可用短、可停、加载失败回到静态的已批准品牌片段。当前包没有输出新的品牌资产，没有将截图裁成素材，也没有修改任何原图。审批前可只显示现有品牌文字和布局，不伪造肖像替代品。

留在Web：人物解构重组、滚动驱动变形、粒子字、复杂呼吸与运动模糊，以及光束／金属／液态装饰实现。小程序保留“影像先行、细线蓝灰、安静留白、单一动作”，不迁移Three.js、WebGL、GLSL、粒子数据结构或任何重动画引擎。
